# platen web

The frontend: Dioxus compiled to WebAssembly. It draws an isometric typewriter, runs the test
in the browser, sends the keystroke log to the server and shows the verified result.

| Path | What it holds |
|---|---|
| `src/` | The app. `main.rs` holds the page; `session.rs` models a test as it is typed. |
| `assets/` | Stylesheets, the generated typewriter drawing and the typewriter sounds. |
| `PRODUCT.md`, `DESIGN.md` | Who the product is for and its design system. |
| `.impeccable/` | Design tool records: the design tokens and the typing screen brief. |

## Setup

The frontend needs the `wasm32-unknown-unknown` target and the Dioxus CLI.

```bash
rustup target add wasm32-unknown-unknown
```

```bash
cargo install dioxus-cli@0.7.10 --locked
```

## Develop

Run the server (see the main README), then the frontend dev server from this directory. The
dev server proxies `/api` to port 3000. Open the URL `dx` prints.

```bash
dx serve --platform web
```

## Production bundle

Bundle the frontend from this directory. The server's `.env.example` already points
`STATIC_DIR` at the result, `web/dist/public`, so the server serves the app at `/` beside the
API. The release profile optimises the bundle for download size.

```bash
dx bundle --platform web --release --out-dir dist
```

## The typewriter drawing

`assets/typewriter.json` is generated by `scripts/figure/build.mjs`. Rerun that script after
changing the figure; CI fails when the committed drawing is stale. See `scripts/README.md`.
